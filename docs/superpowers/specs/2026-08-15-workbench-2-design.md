# 政务工作台 2.0 设计文档

日期：2026-08-15 ｜ 状态：已批准（存储选 A） ｜ 范围：tizhi-agent-ui v0.2.0

## 目标

把 v0.1.11 的「模块 = 预填模板」升级为**右侧抽屉工作台**：每个模块是可管理的
条目集合（增删改、状态流转），条目再挂「交给大前辈」智能动作——用条目的
结构化数据组装丰富上下文开会话。

## 关键决策

| 决策 | 理由 |
|---|---|
| 右侧固定抽屉（fixed right，~360px，全高），挂 shell.overlay | 官方右侧详情列是会话作用域单槽且被工具详情占用；抽屉无会话也可用、不受官方布局升级影响 |
| 侧栏底部「政」按钮 = 抽屉开关 | 入口沿用 v0.1.11 |
| 统一条目框架：ModuleDef{fields, statuses, actions} + Entry{module, status, fields} | 五个模块共享一套 CRUD/状态流转/表单渲染，新模块=加一条配置 |
| 存储选 A：localStorage（`tizhi-agent-ui.workbench-data`）+ 导出/导入 JSON 兜底 | 树外插件唯一持久化通道；数据按浏览器隔离，导出兜底迁移 |
| 模块定义 v1 内置在代码（workbench-config.ts） | 字段/动作结构比 launcher 列表复杂，YAML 化留待生态期；modules.yml 路由保留但抽屉不再消费 |
| 动作复用 launchFromRoot（复用/新开空白会话 → 切体制模式 → setDraft） | v0.1.11 已验证的链路 |
| 仅体制模式开启时显示 | 与品牌开关同生命周期 |

## 模块配置

| 模块 | 字段 | 状态流 | 动作（build 模板要点） |
|---|---|---|---|
| 会议安排 | 议题/时间/地点/参会范围/备注(多行) | 待开→已开 | 生成通知·议程；整理纪要（带全部字段） |
| 每周总结 | 周次/素材要点(多行随手记) | 积累中→已成稿 | 生成总结（要点全量进 prompt，按亮点数据问题下周组织） |
| 思想学习 | 主题/篇目来源/要求 | 待学→已学→已写心得 | 生成心得（结合本职工作，不空喊口号） |
| 汇报材料 | 事项/对象/场合/要点(多行) | 准备中→已汇报 | 生成提纲（按对象场合定调） |
| 公文起草 | 文种/事由/主送机关 | 草拟中→已定稿 | 起草（先出大纲确认再展开） |

空字段在模板中以「……」占位，由大前辈摸底补齐。

## UI 结构

抽屉 = 头部（标题+关闭）→ 模块页签行（5 chips，带各自条目计数）→ 当前模块
条目列表（卡片：首字段为题、状态胶囊可点切换、编辑/删除/动作按钮）→
「+ 新增」内联表单 → 底部（导出 JSON / 导入 JSON）。编辑态为组件本地 state，
仅提交时写 store。

## 验收

1. 抽屉开合、五模块页签切换、条目增删改、状态点击流转；
2. 刷新后条目保留（localStorage）；
3. 条目动作 → 新会话体制模式 + 组装了字段数据的开场文本；
4. 导出得到 JSON 文件、导入能还原；
5. 关闭体制模式后按钮与抽屉同隐。
